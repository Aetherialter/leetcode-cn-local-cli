## 待定决策

### PB-002：扩展调试输出与 Doctor 执行信息

待决定：

- 是否新增 `lc test --verbose` 展示完整用户 traceback。
- `lc doctor --run-solution` 是否永久保持静默，只报告退出码或超时。

### PB-003：远程提交退出码

待决定：进程退出码表达“请求已成功发送”，还是表达“最终判题通过”。必须覆盖 `Accepted`、所有非 Accepted 状态、请求失败、认证失败和轮询超时。

建议候选语义：只有 `Accepted` 返回 0；非 Accepted 和运行失败返回非零；命令参数错误返回 2。

2026-07-30 Windows Mock 验收已确认：Wrong Answer 和轮询超时虽然会显示失败或超时信息，CLI 仍可能返回 0。真实验收只执行了一次 Accepted 提交，没有为了制造失败而增加远端副作用。

### PB-004：提交前本地校验

待决定：`lc submit` 在远程请求前是否编译整个 `solution.py`、提交 marker 区域，或完全交给 LeetCode 判定。该决定不得让 `lc submit` 隐式执行用户代码。

### PB-006：`solution.py` 编码

待决定：只接受 UTF-8，还是支持 Python 编码声明或自动猜测本地编码。当前生成文件为 UTF-8；非 UTF-8 文件会触发尚未收敛的读取异常。

2026-07-30 Windows 验收已稳定复现：非法 UTF-8 字节会让 `lc test`、`lc doctor` 和 `lc submit` 以 `UnicodeDecodeError` traceback 退出。无论最终选择哪种编码策略，普通 CLI 都应把编码失败映射为受控错误，不应向用户暴露内部 traceback。

### PB-007：编辑器配置模型

待决定：命令参数、工作区配置、用户配置、环境变量和系统默认关联之间的优先级，以及编辑器配置使用单个命令字符串还是参数数组。配置设计必须避免通过 Shell 拼接执行命令。

### PB-010：分页越界

待决定：合法但超过题目总数的 `show --skip` 返回空结果、友好提示并成功结束，还是作为用户错误返回非零。非法负数和远端结构异常必须与合法空页区分。

### PB-011：Broken Pipe

待决定：`lc --help | head` 等下游提前关闭管道的场景是否视为正常结束，以及是否统一返回 0。

### PB-012：Python 支持范围

待决定：继续声明无上限的 `Python >=3.12`，还是只支持 CI 实际覆盖的小版本范围；同时明确 uv 是否允许自动使用 managed Python。

### PB-013：Git 工作区标记的版本控制语义

当前在 Git 仓库根目录执行 `lc init` 会创建 `.leetcode-local-cli.toml`，但项目不会自动修改 `.gitignore`。因此标记可能作为未跟踪文件出现在工作树中。

待决定：

1. 工作区标记是可提交的共享配置，由项目维护者决定是否纳入版本控制。
2. 工作区标记是纯本机配置，应由用户或模板明确忽略。
3. 调整标记位置或发现机制，使工作区识别不依赖仓库根目录中的未跟踪文件。

实现不得静默修改任意仓库的 `.gitignore`，除非这一外部副作用经过单独产品确认。

## 决策规则

每项待定边界拍板后，应完成以下同步：

1. 将结论、日期和适用版本写入本文件，并从“待定决策”移动到“已确认边界”。
2. 更新 README 的用户可见行为。
3. 更新 `DEVELOPMENT_PLAN.md` 的实施阶段与验收标准。
4. 如影响长期架构，更新 `PROJECT_DESIGN.md`。
5. 如影响安全或数据完整性，更新 `SECURITY_REVIEW.md`。
6. 实现代码与测试必须引用同一行为语义，不得只修改文档或只修改测试。
