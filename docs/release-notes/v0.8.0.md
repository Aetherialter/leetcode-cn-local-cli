v0.8.0 — 显式工作区与安装后初始化

leetcode-local-cli 0.8.0 引入显式默认工作区、版本化配置和安装后初始化。

## 新增

- 新增跨平台用户配置、版本化工作区配置和不可变 `AppPaths` 运行上下文。
- 新增 `lc init [path]`；支持交互选择父目录，也支持 `lc init <完整路径> --yes` 自动验收。
- 官方 uv 安装脚本在可交互终端继续配置工作区；非交互环境安全跳过并给出手动命令。

## 改进

- 普通命令从任意目录运行时都使用明确的默认工作区，不再依赖模块导入时的当前目录。
- `lc init` 保留已有普通 `solution.py`，重复执行幂等；版本更新直接复用有效工作区。
- `solution.py`、Session 和用户配置使用随机同目录临时文件与原子替换，写入失败时保护旧文件。
- 符号链接、断链、目录、junction、Windows reparse point 和损坏配置会被明确拒绝。

## 兼容性与安全

- 当前仍采用单工作区、单个 `solution.py`、LeetCode 中文站和 Python3 提交。
- Session 暂时保存在默认工作区的 `.leetcode_local_cli/session.json`，不会迁移旧 `.aether_lc/session.json`；升级后请重新执行 `lc login`。
- Session 是明文秘密，不能输出、提交、同步或上传。CI 仍只使用假 Cookie，不执行真实远程提交。
- 直接执行 `uv tool install leetcode-local-cli` 后需要手动运行 `lc init`。
