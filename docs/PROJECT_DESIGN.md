# 长期方向

状态：方向参考，不是版本计划、公开承诺或已确认设计。

当前实现和近期工作分别以 [PROJECT_STATUS](PROJECT_STATUS.md)、[ARCHITECTURE](ARCHITECTURE.md) 和 [DEVELOPMENT_PLAN](DEVELOPMENT_PLAN.md) 为准。下面任何方向进入开发前，都必须基于当时源码重新需求分析、技术设计和产品确认。

## 长期目标

形成一个跨平台、可维护的 LeetCode 工具：稳定 CLI 与 Python API 共享同一核心，最终可以支持中文站与国际站，同时继续保持轻量、在线优先和明确的安全边界。

## 大体方向

1. **稳定核心**：核心模型、异常、用例和站点协议不依赖 Typer、Rich 或终端。
2. **双站点**：通过站点适配器隔离域名、Cookie、请求和账号，不在业务代码中散布站点判断。
3. **凭据安全**：评估 Windows Credential Manager、macOS Keychain 和 Linux Secret Service；必须设计无后端降级和迁移策略。
4. **Python API**：只公开已稳定且有真实消费者的能力，提供类型、兼容策略和构建后契约测试。
5. **内容与体验**：核心稳定后再评估结构化题面、图片降级、编辑器集成和终端 UI。
6. **发布质量**：持续完善跨平台安装、CI、依赖安全和真实环境的脱敏手动验收。

## 保持不变的原则

- CLI 与 Python API 复用业务实现，展示层不决定业务结果。
- 配置、工作区和秘密分层；路径由运行上下文显式传递。
- 外部输入不可信；文件、终端、子进程、浏览器和网络都有明确边界。
- 基础 CLI 不强制数据库、Web、AI、后台服务或多语言运行时。
- 不用未来架构目标为当前小功能引入框架或大规模重写。

## 重新立项时必须回答

- 谁是实际使用者，当前问题是否已经存在？
- 公开行为、数据格式或兼容性会怎样变化？
- 哪个模块负责，依赖方向是否仍然单向？
- 凭据、文件系统、网络和跨平台风险是什么？
- 最小交付是什么，怎样自动验证和手动验收？
